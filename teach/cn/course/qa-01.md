<!-- columns: 50/50 -->

## 为什么选择 token-level reward 而不是 sequence-level reward？

<!-- footnote-right: 来源：[@dejavukun on YouTube (Lecture 3)](https://www.youtube.com/watch?v=K_Sj_-1BUMM&lc=Ugz9joGHibucDB5llqJ4AaABAg) -->

注意：这里有两种不同的含义。

- **Reward 粒度：** 最终答案 reward vs 步骤/token reward（PRM、KL、格式 reward）[@lightman2023let]。
- **Loss 粒度：** 按序列平均 vs 按有效 token 平均；DAPO 使用 token-level policy-gradient loss [@yu2025dapo]。

```python
# Sequence-normalized: each completion has equal weight
loss = ((pg_loss * mask).sum(dim=1) / mask.sum(dim=1)).mean()

# Token-normalized: each generated token has equal weight
loss = (pg_loss * mask).sum() / mask.sum()
```

|||

token-level 为什么有帮助：
- 局部信号：KL、格式 reward、PRM、部分得分
- long-CoT RL：对实际采样到的 token 施加更多梯度
- batching：按有效 token 而非样本数归一化
- DAPO：面向推理 RL 的 token-level loss + Clip-Higher + dynamic sampling [@yu2025dapo]

反方观点：如果 reward 只是最终答案是否正确，sequence-level advantage 仍然很自然；GSPO 把 ratio 重新拉回 sequence level [@zheng2025gspo]。

## $\rho$ 的形状是什么？

<!-- columns: 50/50 -->

## $\rho$ 的形状是什么？

<!-- footnote-right: 来源：[@JGLambourne on YouTube (Lecture 3)](https://www.youtube.com/watch?v=K_Sj_-1BUMM&lc=UgwC9D0I4zmtGtyyGz14AaABAg) -->

$$\rho_t(\theta) = \frac{\pi_\theta(a_t \mid s_t)}{\pi_{\theta_\text{old}}(a_t \mid s_t)}$$

- $\pi(\cdot \mid s_t)$ 的形状与词表相同：`[B, T, V]`
- $\pi(a_t \mid s_t)$ 是在采样 token 处 gather 得到的：`[B, T]`
- $\rho_t$ 是每个 token 一个标量；rollout 张量为 `[B, T]`

|||

```python
# logits/logprobs over vocab: [B, T, V]
old_logps_all = old_policy.log_softmax(logits_old, dim=-1)
new_logps_all = policy.log_softmax(logits_new, dim=-1)

# sampled token ids: [B, T]
actions = input_ids[:, 1:]

# gather only the probabilities of the sampled tokens: [B, T]
old_logps = old_logps_all.gather(-1, actions.unsqueeze(-1)).squeeze(-1)
new_logps = new_logps_all.gather(-1, actions.unsqueeze(-1)).squeeze(-1)

# importance ratio per sampled token: [B, T]
rho = torch.exp(new_logps - old_logps)
```

## 为什么 PPO 的 policy loss 和 value loss 都使用 `torch.max`？

<!-- footnote-right: 来源：[@jacoboromerodiaz6967 on YouTube (Lecture 4)](https://www.youtube.com/watch?v=i-AIMpZHgeg&lc=UgwjmSeeAuvtuN_B85R4AaABAg) -->

```python
# PPO minimizes a negative policy loss
pg_loss_unclipped = -advantages * ratio
pg_loss_clipped = -advantages * torch.clamp(
    ratio, 1.0 - eps, 1.0 + eps
)

# choose the more conservative / worse loss
pg_loss = torch.max(pg_loss_unclipped, pg_loss_clipped)
```

`torch.max` 之所以重要，是因为 PPO 被写成一个**需要最小化的 loss**。

它会选择裁剪后改进更小的那个更新。

|||

```python
# value clipping: do not let critic jump too far
v_clip = old_values + torch.clamp(
    v_pred - old_values, -vf_eps, vf_eps
)

vf_unclipped = 0.5 * (v_pred - targets) ** 2
vf_clipped = 0.5 * (v_clip - targets) ** 2

# optimize the worse value error
vf_loss = torch.max(vf_unclipped, vf_clipped)
```

Policy clipping 限制 policy 的漂移。

Value clipping 限制 critic 的漂移。

模式相同：比较未裁剪与裁剪后的 loss，用更差的那个来训练。
